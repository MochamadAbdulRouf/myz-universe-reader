1. Membuat file "entrypoint.sh" untuk menyuntikan nilai environment variable (SUPABASE_URL dan SUPABASE_PUBLISHABLE_KEY) ke dalam file Java Script.Lalu file java script mana yang dimaksud? file javascript tersebut biasanya akan muncul setelah menjalankan command "npm run build" pada proyek React, TypeScript, dan Vite. Proses build akan mengkompilasi semua kode sumber seperti (file .ts, .tsx, dll) menjadi beberapa file statis yang di optimalkan. File java script utamanya akan diberi nama dengan pola "index-[hash(acak)].js".

```bash

WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# --- Tahap Produksi ---
FROM nginx:stable-alpine

# Salin file statis dari tahap build
COPY --from=builder /app/dist /usr/share/nginx/html

# ----------------- PERUBAHAN DI SINI -----------------

# Salin skrip entrypoint ke dalam image
COPY entrypoint.sh /entrypoint.sh

# Beri izin eksekusi lagi di dalam image (sebagai jaminan)
RUN chmod +x /entrypoint.sh

# Jalankan skrip entrypoint sebagai perintah utama container
CMD ["/entrypoint.sh"]
```

## Implementasi Blue Green Deployment 
Implementasi ini bertujuan agar update aplikasi terbaru masuk ke deployment blue dulu, lalu kita implementasikan deployment green dengan zero user yg mengaksesnya dan memastikan tidak ada bug di update aplikasi terbaru. nanti ketika sudah selesai tinggal kita alihkan traffic semua user ke deployment green.

1. Buat namespace baru bernama `blue-green`
```bash
kubectl create ns blue-green
```

2. edit file manifest `comic-deployment-secure.yaml` seperti ini, ganti semua label menjadi blue.
```bash

apiVersion: v1 
kind: Secret
metadata:
  name: comic-secret
stringData:
  VITE_SUPABASE_PROJECT_ID: "nurpudorwottgiffizac"
  VITE_SUPABASE_PUBLISHABLE_KEY: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSIsInJlZiI6Im51cnB1ZG9yd290dGdpZmZpemFjIiwicm9sZSI6ImFub24iLCJpYXQiOjE3NTk5MTA4MDIsImV4cCI6MjA3NTQ4NjgwMn0.3N9GgigDy9QToWBfN_C-K1zNFCHJkZPajNR0tXDGtmA"
  VITE_SUPABASE_URL: "https://nurpudorwottgiffizac.supabase.co"

--- 

apiVersion: apps/v1
kind: Deployment
metadata:
  name: comic-deployment
  labels:
    app: blue
spec:
  replicas: 3
  selector:
    matchLabels:
      app: blue 
  template:
    metadata:
      labels:
        app: blue 
      annotations:
        developer: mochabdulrouf 
        mode: production
    spec:
      containers:
        - name: comic-container
          image: mochabdulrouf/react-comic-app:3.1-production-secure
          ports:
            - containerPort: 80
          envFrom:
            - secretRef:
                name: comic-secret
            
---

apiVersion: v1 
kind: Service
metadata:
  name: svc-blue-green # implementasi blue green deployment nama servicenya aku ubah yaa
spec:
  type: NodePort
  selector:
    app: blue 
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30002
```

3. Lakukan blue deployment terlebih dahulu 
```
kubectl -n blue-green apply -f comic-deployment-secure.yaml
```

4. Buat file manifest untuk green deployment
```bash 
cp comic-deployment-secure.yaml comic-deployment-secure-update.yml
```

5. edit file manifest `comic-deployment-secure-update.yml`, ubah nama deployment menjadi `comic-deployment-update`, lalu ganti label tadinya `blue` jadi `green` dan hapus bagian service

## Implementasi Canary Deployment 

note: untuk canary deployment, pada deployment pertama saya menggunakan image aplikasi comic dan deployment canarynya saya pakai web server apache default. supaya bisa membedakan traffic hasil live curl nanti.
1. Membuat namespace khusus canary 
```bash
kubectl create ns canary
```

2. Saya mengubah nama deployment dan label serta service menjadi seperti berikut 
```bash
apiVersion: apps/v1
kind: Deployment
metadata:
  name: main
  labels:
    app: main
spec:
  replicas: 3
  selector:
    matchLabels:
      app: main
  template:
    metadata:
      labels:
        app: main
      annotations:
        developer: mochabdulrouf
        mode: production
    spec:
      containers:
        - name: comic-container
          image: mochabdulrouf/react-comic-app:3.1-production-secure
          ports:
            - containerPort: 80
          envFrom:
            - secretRef:
                name: comic-secret

---

apiVersion: v1
kind: Service
metadata:
  name: main-service
spec:
  type: NodePort
  selector:
    app: main
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30005
```

3. Melakukan deployment pertama 
```bash
kubectl -n canary apply -f comic-deployment-secure.yaml 
```

4. Di implementasi ini, saya mengubah nama deployment, image menjadi httpd dan replica setnya menjadi 1, dan menghapus service. 
```bash
apiVersion: apps/v1
kind: Deployment
metadata:
  name: canary
  labels:
    app: canary
spec:
  replicas: 1
  selector:
    matchLabels:
      app: main # di bedakan karena target service hanya ke labels main, jadi nanti service akan membagi traffic ke web comic dan apache default 
  template:
    metadata:
      labels:
        app: main #
      annotations:
        developer: mochabdulrouf
        mode: production
    spec:
      containers:
        - name: comic-container
          image: httpd
          ports:
            - containerPort: 80
          envFrom:
            - secretRef:
                name: comic-secret
```

5. lalu lakukan canary deployment 
```bash
kubectl -n canary apply -f comic-deployment-secure-update.yml 
```

7. Untuk melihat traffic yang di distribusikan secara live bisa menggunakan command berikut 
```bash
watch -n 1 curl IP:NODEPORT 
```
example 
```bash
watch -n 1 curl 192.168.1.1:30008
```
note: jadi saat ini ada 3 pods `comic` dan 1 pods `apache` total pods ada 4, maka 100% traffic akan dibagi menjadi 75% ke pod `main(comic)` dan 25% ke pods `canary(apache)` 

8. sebenarnya untuk canary deployment hanya 10% user yg bisa akses deployment `canary` dan 90% user masih mengakses deployment `main`, yang nantinya akan di tingkatkan secara bertahap ke deployment `canary` (10% -> 25% -> 50% -> 75% -> 100%). jadi kita ubah aja replica untuk main sekarang menjadi `9 pods`.

9. tambahkan replica deployment main
```bash
kubectl scale deployment main --replicas 9 
```
example:
```bash
root@rouf:~/myz-universe-reader/Production/secure-config# kubectl -n canary scale deployment main --replicas 9
deployment.apps/main scaled

```

